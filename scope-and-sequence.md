# Scope and Sequence: F26 Transition Year

This document assigns every Technical Lecture session of the F26 fellowship to a week, a day, and a topic. Environment setup and virtual environments are covered in orientation, before day 1, so the first Technical Lecture session is Command Line Interfaces. Technical Lecture is one 90-minute session per day on Monday, Wednesday, Thursday, and Friday; Tuesday has no session. Each calendar gives a session's week within the quarter, its weekday as a number, so 1 is Monday and 5 is Friday, and its date. A holiday makes a short week of three sessions rather than moving the days that remain. Technical Interview Prep runs in the daily Code Challenge block, so it does not appear here. The fellowship starts on Monday, September 28, 2026 and the capstone begins on Monday, June 7, 2027.

The three breaks fall on the quarter boundaries. Q1 ends on Friday, December 18 before winter recess. Q2 ends on Friday, March 19 before spring break. Q3 ends on Friday, May 28 before the summer office closure. There is no review week between units; every session carries content or assessment, apart from the unassigned Q1 days listed in the Q1 section.

## Calendar

Breaks: winter recess December 21 to January 4, spring break March 22 to 26, summer office closure May 31 to June 4.

Holidays assumed off and removed from the counts below: Indigenous Peoples' Day (October 12), Veterans Day (November 11), Thanksgiving (November 26), MLK Day (January 18), Presidents' Day (February 15), Juneteenth observed (June 18), and Independence Day observed (July 5). The Wednesday before Thanksgiving is a teaching day.

## Q2: Fullstack and AI-Assisted Development

Forty-one sessions. The quarter opens on Wednesday, January 6 by introducing implementer mode, and the first session teaches the workflow fellows will use for the rest of the year. Every fellow is expected to begin practicing implementer mode in Q2, so each Q2 assignment offers a tutor-mode option and an implementer-mode option. HTML, CSS, and Jinja take six sessions, HTTP and APIs take three, Flask takes seven, Postgres takes ten, the AI strand takes three including the opening, verification takes four, and the project with its architecture defense takes eight.

Four chapters run as assigned reading rather than a lecture: the Box Model, Grid and Media Queries, Accessibility, and Aggregates and Seeding. Passwords, sessions, authorization, and user-owned resources are compressed to two sessions because the Q3 Security module hardens the authentication those two sessions establish. Production deployment is the Q3 Deployment module.

The four verification sessions are Group 5 material and are named sessions so that Flask and Postgres content does not absorb them. The remaining Q2 AI topics not covered in the three lecture sessions run in Leadership Seminar.

## Q3: AI-Led Project Building and Systems Design

Thirty-six sessions. Every fellow rotates through five systems modules built against a shared CRUD application. Each module runs the 24-hour spec loop over seven sessions, and the mentor stack review takes the final session. Deployment runs first so that the application is live from the second week of the quarter and every later module's presentation happens against a running URL rather than a local server. Technical Lecture in Q3 is structured build time with instructor check-ins; each module's ideas are introduced in seminar on its first day.

| Module                      | First session | Last session | Sessions |
| --------------------------- | ------------- | ------------ | -------- |
| Deployment and Environments | Mon 3/29      | Thu 4/8      | 7        |
| Security                    | Fri 4/9       | Wed 4/21     | 7        |
| Testing                     | Thu 4/22      | Mon 5/3      | 7        |
| Cost                        | Wed 5/5       | Fri 5/14     | 7        |
| Bottlenecks and Sandboxing  | Mon 5/17      | Thu 5/27     | 7        |
| Mentor stack review         | Fri 5/28      | same day     | 1        |

Each module follows the same seven-session shape:

| Session | Activity                                                          |
| ------- | ----------------------------------------------------------------- |
| 1       | State the problem; interrogate the stakeholder about requirements |
| 2       | Return with a spec; receive feedback                              |
| 3       | Return with tools and approach                                    |
| 4 to 6  | Implement                                                         |
| 7       | Present; constraint-specific salted review                        |

Q3 has no slack. Thirty-six sessions of demand sit in thirty-six sessions of supply, and the spec loop is clock-bound, so a mentor absence or a closed day removes a module's presentation rather than delaying it. The cost-and-failure audit pairs with the Cost module's session 7. Live interview practice runs in Code Challenge.

## Q4: Capstone

June 7 to August 27, forty-six sessions across twelve weeks, for a real stakeholder. The stakeholder requirement translation assessment runs in the first two weeks; the handoff test, cold-context handoff, and full-cycle review run in the final week.

## Decisions this schedule depends on

- Leadership Seminar carries the ethics, academic-impact, and policy content of the AI strand in Q1, and the AI topics not given lecture sessions in Q2. If it cannot, Q1 needs two more sessions and Q2 needs two more, and neither quarter has them.
- Q3 runs five modules. Folding Bottlenecks and Sandboxing into Security, or pairing it with Cost, would free seven sessions and give Q3 its only buffer.
